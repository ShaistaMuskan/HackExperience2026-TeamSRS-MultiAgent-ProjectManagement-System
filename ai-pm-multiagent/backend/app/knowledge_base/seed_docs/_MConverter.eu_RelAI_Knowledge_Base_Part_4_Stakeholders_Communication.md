Rel.AI Project Management Knowledge Base\
Part 4 -- Stakeholder Management, Cross-Functional Collaboration & Communication {#rel.ai-project-management-knowledge-base-part-4-stakeholder-management-cross-functional-collaboration-communication}
================================================================================

## Purpose

This document teaches Rel.AI how to determine who should be informed, consulted, approve decisions, or take action whenever project changes occur.

## 1. Stakeholder Classification {#stakeholder-classification}

Classify stakeholders by:\
• Role\
• Department\
• Decision authority\
• Influence\
• Interest\
• Communication needs\
• Approval authority\
• Project impact

## 2. Stakeholder Prioritization {#stakeholder-prioritization}

Use a Power--Interest Matrix:\
High Power / High Interest → Manage Closely\
High Power / Low Interest → Keep Satisfied\
Low Power / High Interest → Keep Informed\
Low Power / Low Interest → Monitor

## 3. Cross-Functional Team Playbooks {#cross-functional-team-playbooks}

Engineering\
Needs: technical requirements, blockers, dependencies, implementation tasks.\
\
Product\
Needs: priorities, roadmap changes, scope, acceptance criteria.\
\
Design\
Needs: UX changes, assets, design approvals.\
\
QA\
Needs: testing scope, defects, regression impact, release readiness.\
\
Marketing\
Needs: launch dates, feature availability, messaging changes.\
\
Legal & Compliance\
Needs: contracts, regulatory changes, approvals, audits.\
\
Operations\
Needs: deployment readiness, support plans, operational impacts.\
\
Executives\
Needs: project health, milestones, risks, budget, delivery confidence.

## 4. Communication Matrix {#communication-matrix}

Update Type → Audience\
\
Technical Change → Engineering, Product\
Timeline Change → PM, Executives, Marketing\
Compliance Change → Legal, PM\
Resource Change → Team Leads\
Critical Risk → PM, Sponsor, Executive Leadership\
Release Change → Engineering, QA, Marketing, Support

## 5. Escalation Framework {#escalation-framework}

Escalate when:\
• Critical path is blocked.\
• Major milestone slips.\
• Budget threshold exceeded.\
• Security or compliance issue identified.\
• Customer commitment is at risk.\
• Executive decision required.

## 6. Meeting Playbooks {#meeting-playbooks}

Kick-off:\
Objectives, scope, stakeholders, risks.\
\
Stand-up:\
Progress, blockers, next actions.\
\
Sprint Review:\
Completed work, demonstrations, feedback.\
\
Retrospective:\
Successes, improvements, lessons learned.\
\
Steering Committee:\
Project health, decisions, escalations.

## 7. Reporting Standards {#reporting-standards}

Executive reports should contain:\
• Overall health\
• Key achievements\
• Risks\
• Decisions required\
• Upcoming milestones\
\
Team reports should contain:\
• Assigned work\
• Dependencies\
• Blockers\
• Immediate actions.

## 8. Rel.AI Coordination Rules {#rel.ai-coordination-rules}

For every project update:\
1. Identify affected stakeholders.\
2. Determine information required by each audience.\
3. Tailor communication to stakeholder role.\
4. Avoid unnecessary notifications.\
5. Highlight required actions.\
6. Escalate only when predefined thresholds are met.
